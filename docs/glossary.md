# Glossary

| Term | Meaning |
|------|---------|
| **Aggregate** | An entity with its own lifecycle and a single owner that emits its facts (change, run, job, plan, proposal, release, deployment) |
| **Autonomy level (L0–L4)** | How far agent proposals may be applied without a human, per repo, for delivery-plane remediation; work-plane changes always need plan approval and human merge ([07 §4](07-agents.md#4-control-model)) |
| **Build Plan** | Declarative DAG of jobs for a repo, generated by the Build Planner or authored in the manifest, cached by fingerprint. Also supplies inner-loop commands to coding sessions. |
| **Canonical event** | A provider-agnostic, registry-validated event (L1–L3) in the CloudEvents envelope |
| **Causation ID** | ID of the event that directly caused this one |
| **Change** | Provider-agnostic pull request / merge request |
| **Changeset** | The group of changes across several repos that implement one work item. Integration-tested together and merged in dependency order. |
| **Coding session** | A long-running agent session for one (work item, repo): Test Author + Coding agent in a dev sandbox, iterating until the change is green ([14 §6](14-work-plane.md#6-coding-sessions)) |
| **Concurrency group** | Key that defines which runs supersede or queue behind each other |
| **Correlation ID** | Shared ID for all events from one root stimulus (one change, release, schedule firing) |
| **Dev sandbox** | An isolated, session-lived environment with a writable checkout and toolchain, for the inner loop. No production secrets. |
| **Diagnosis class** | Normalised failure category (`code`, `test-flaky`, `dependency`, `infra`, …) |
| **Ephemeral environment** | A short-lived deployment of a change (or changeset) with its neighbours for integration testing ([15](15-integration-testing.md)) |
| **Failure attribution** | Deciding which repo or service caused an integration failure, including control runs against baseline |
| **Feedback Router** | The handler that sends pipeline, integration and review feedback on agent-owned changes to the owning session |
| **Fingerprint** | Hash of everything that determines how a repo builds. A change means plan regeneration. |
| **Handler** | Named consumer that subscribes to canonical events and decides or acts ([13](13-event-handlers.md)) |
| **Implementation plan** | The versioned, structured plan for a work item that the developer must approve before coding starts. Distinct from the **Build Plan**. |
| **Inner loop / outer loop** | Fast, non-authoritative build and test in the dev sandbox / the full, authoritative delivery pipeline on every push |
| **Intent** | An event requesting an action (`…requested`). It may be rejected. |
| **Manifest** | Optional `.agentic/pipeline.yaml` in a repo |
| **ap-sidecar** | The process in each executor that emits typed build-process events. **Not** an LLM agent. |
| **Proposal** | Typed output of an LLM agent (patch, PR, plan, comment, quarantine…) awaiting the policy decision |
| **Raw archive** | Unchanged store of every received webhook (L0) |
| **Scope envelope** | The repos, path globs and forbidden paths an approved plan allows. Enforced by the Scope Guard. |
| **Scope ledger** | Projection of everything ignored or rejected, and why |
| **Scope matrix** | Rule table that maps canonical events to pipeline intents ([06 §4](06-pipeline-lifecycle.md#4-scope-matrix-trigger--pipeline)) |
| **Sponsoring developer** | The person who assigned the task to the agent. Gives guidance, approves the plan, answers clarifications, reviews the PR. |
| **Supersession** | Cancelling or deprioritising an older run when a newer head arrives for the same group |
| **Test Author** | A separate agent instance that writes tests from the plan and acceptance criteria before the implementation exists |
| **Tier (B/S/T)** | Emission tier for build-process events: bus, summary, telemetry ([12 §3](12-build-process-events.md#3-emission-tiers)) |
| **Work item** | A tracker task (Jira issue) handled by the work plane. The root correlation `wi-<tenant>-<KEY>`. |
